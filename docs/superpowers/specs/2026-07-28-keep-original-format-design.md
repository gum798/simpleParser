# 원본 유지 정렬(비파괴 정렬) 설계

날짜: 2026-07-28
상태: 승인됨 (사용자 선택: "OUTPUT에 결과 표시" 방식)

## 문제

[정렬]은 `editor.setValue(정렬 결과)`로 입력창 내용을 교체한다. 로그를 붙여넣고 정렬하면
JSON 블록만 남고 로그 접두어 등 주변 텍스트(원본 데이터)가 사라진다. 사용자는 원본을
지우지 않고 정렬 결과를 보는 옵션을 원한다.

## 결정

1. **[원본 유지] 토글(툴바, [정렬] 옆)**
   - 개인 취향 설정 → localStorage `simpleparser.keepOriginal`에 저장(규칙창 도킹과 동일 패턴). 기본 꺼짐.
   - 꺼짐: 기존 동작 100% 유지(기존 테스트 36개가 그대로 통과해야 함).
   - 켜짐: 수동 [정렬]도, 붙여넣기 자동 정렬(safeOnly)도 입력창을 절대 수정하지 않는다.
     수동 [정렬]은 OUTPUT 패널을 열고 텍스트 뷰로 전환해 정렬 결과를 보여준다.

2. **OUTPUT 패널에 [트리|텍스트] 뷰 전환(미니 세그먼트, 패널 헤더)**
   - markdown(미리보기 전용)에는 표시하지 않는다.
   - 텍스트 뷰: `format(입력, 포맷).output`을 `<pre>`로 표시. output이 없으면 안내 문구.
   - 텍스트 뷰에도 하이라이트 규칙 색을 적용한다(트리 라벨과 동일 규칙 — tree.ts의
     라벨 하이라이트 로직을 `highlightText`로 export해 재사용).
   - 텍스트 뷰 전용 [복사] 버튼(패널 헤더): 정렬 결과를 클립보드로. 트리 뷰에서는 뎁스
     컨트롤이, 텍스트 뷰에서는 복사 버튼이 보인다.
   - 뷰 상태는 세션 변수(URL/localStorage 저장 안 함) — 원본 유지 정렬이 자동으로 텍스트
     뷰를 열어주므로 주 흐름에는 충분.

3. **진단**: 원본 유지 정렬 시 진단은 정렬 전 입력 기준(before)을 표시한다(입력창이
   그대로이므로 오프셋이 일치).

## 범위 밖 (YAGNI)

- URL 상태 스키마 변경(뷰 모드/토글의 공유 링크 반영) — 하지 않음.
- 로그 속 JSON 제자리 정렬(주변 텍스트 유지한 채 입력 수정) — 다른 방식이라 제외.
- 텍스트 뷰 구문 강조(syntax highlight) — 하이라이트 규칙 색만 적용.

## 테스트

- e2e: ① 토글 켜고 정렬 → 입력 불변 + OUTPUT 텍스트에 정렬 결과 ② 토글 상태 새로고침
  유지 ③ 트리/텍스트 전환 ④ 토글 켠 상태 붙여넣기 자동 정렬도 입력 불변 ⑤ 텍스트 뷰 복사
- 기존 유닛 133개 + e2e 36개 무회귀(토글 기본 꺼짐이 보장).
